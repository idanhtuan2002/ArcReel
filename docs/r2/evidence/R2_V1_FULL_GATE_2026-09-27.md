## Failures and their resolution

1. **SQLite: one test timed out.** The test is
   `test_m6_dual_profile_acceptance.py::test_two_dual_profile_slices_share_one_canon_parent_with_isolated_evidence`.
   - It stopped at `Timeout (>1500.0s) from pytest-timeout` during real
     Remotion renders. No assertion failed.
   - Rerun alone on `78479432`, it passed: 1 passed, 806.70 s call time,
     which matches the ~800 s noted in the test.
   - Cause: CPU contention from the concurrent PG16 run. This is an
     inference from the timing; the test itself is unchanged.
2. **PG16: ten H6 tests failed on client/server version skew.** All ten are
   in `test_deployment_backup.py`.
   - `pg_restore` 18 sent `SET transaction_timeout = 0`, which PG16 rejects.
     The runbook documents this limit ("Client/server version
     compatibility").
   - CI installs `postgresql-client` from the Ubuntu runner, and the version
     skew only appears when the client is newer than the server.
   - **Rerun:** the whole file on PG16 with PG16 client tools (the
     `pg_dump`, `pg_restore` and `psql` from the `postgres:16` image,
     through PATH shims) passed 23 of 23 in 59.26 s. This run included the
     fix in item 3.
3. **PG16: one test defect, fixed in `9fd43948`.** The test is
   `test_database_password_never_reaches_tool_argv`.
   - It checked that the password is not a substring of argv. When the
     username equals the password (`arcreel:arcreel`, as in CI), the
     username in the libpq URL matched.
   - The test now checks the URL userinfo password and any conninfo
     `password=` field.
   - The product code is unchanged.
   - After the fix: ruff, basedpyright on the file, and `audit_tests --check`
     are clean, and the file passes on PG16 (item 2).
