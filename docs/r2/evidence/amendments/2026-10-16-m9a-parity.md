# Proposed sponsor decision — M9-A foundation parity scope

Status: PROPOSED, NOT APPROVED. This document grants no implementation release, acceptance, or production authority.

## Verified conflict

The accepted M9-A plan, Task A4.3, requires running the parity verifier. The frozen design §21 requires same-fixture donor/R2 results at the exact integrated HEAD. The reused M8 fold and M9 fold require at least one measured row; an all-EXCLUDED inventory cannot PASS.

M9-A implements native immutable contracts/digests/ports, the strict parity-report verifier, and native Human-custodied profile persistence/API. It contains no verified runtime port of the nine selected OpenMontage/Kalinga/Huohuo donor surfaces. Their exact pins and source bytes are verified by the baseline gate. Mathematical verifier tests are fixtures and do not execute those donor behaviors. No synthetic paired measurement qualifies as production donor parity.

Thus the present plan cannot honestly reach `M9_A_CANDIDATE` with no material unknowns merely by substituting verifier unit tests for actual donor execution. The fresh whole-branch review confirmed this as Important R3 at code HEAD3835011bd856c7a3ffe315aecfa3663a724f6f55.

## Requested bounded decision

Permit a distinct `FOUNDATION_INVENTORY_VERIFIED` parity scope for **M9-A only**, provided all of these conditions hold:

1. The nine exact donor blobs match the accepted baseline pins and complete inventory, with explicit fixture/deferred classifications and no claimed runtime port.
2. Strict parity-verifier regression tests pass, including rejection of absent/tampered fixture and donor/R2 execution outputs. This is verifier verification, not donor behavior PASS.
3. Candidate evidence explicitly records `donor_runtime_executed: false` and `runtime_parity_claimed: false`, and contains no donor report falsely marked PASS.
4. Every other M9-A gate, including real PostgreSQL concurrency/custody/rollback, scoped API/auth/i18n, immutable evidence verification, static checks, and independent review, remains required.
5. Every later packet that actually consumes a selected donor behavior must supply physical paired same-fixture evidence for all eight applicable dimensions at its exact tested HEAD before acceptance. This decision cannot exempt a runtime port, even if one is subsequently added to M9-A.
6. M9-A remains candidate-only; this decision neither approves its code nor releases M9-B or any later packet.

## Changes authorized only after an explicit decision

Record the sponsor decision as a new, immutable, narrowly scoped amendment. Bind its exact bytes/commit in baseline and evidence verification.
