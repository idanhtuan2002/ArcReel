## Source facts

- The first source family is two exact PNG frame receipts from distinct current Gate C episode-video parents. The new `SpatialFrameReader` resolves one receipt to current parent lineage and immutable verified bytes. Its exact-HEAD independent review is still incomplete after the third review was interrupted by a Codex usage limit. See `server/services/spatial_frame_reader.py` and `docs/r2/evidence/R2_M8C_FRAME_CUSTODY_HANDOFF.md`.
- The existing M8 preview path explicitly rejects `PromotionTargetKind.PRODUCTION_BINDING` because it has no authority yet (`r2/advanced_creative/exploration.py:266-267`). `ProductionBinding` is a Pydantic contract with target, role and asset refs (`r2/contracts/preparation.py:20-34`); the bounded runtime search found no persistent target registry, binding-head writer or pair-admission repository in this checkout. The graph result is stale, so this is a bounded source observation rather than a global absence proof.
- ADR-0102 selects an exact Take-derived target registry, one CAS-versioned binding authority and a typed spatial set before M8 promotion (`docs/adr/0102-production-binding-is-a-versioned-production-authority.md`). The M8-C design requires an immutable `SpatialPairAdmission` decision and current head keyed by target/location binding, containing exact target version/digest, binding core digest, ordered MASTER/REVERSE frame receipt IDs/digests, authorized reviewer decision and camera-relation evidence (`docs/superpowers/specs/2026-09-30-r2-m8c-binding-authority-design.md:22-31`). A target or binding change invalidates pair currentness.
- Canonical approve and reject pair-decision vectors already exist in `tests/fixtures/r2/m8c_source_digest_vectors.json`. They establish proposed byte/digest shapes only; the vector cannot prove reviewer authorization, suitable camera geometry or current parent media. The synthetic Gate C fixture can approve two distinct video heads, but different video digests can decode to the same visible frame (`docs/research/2026-09-30-r2-m8c-spatial-source-custody.md`).

## Sequencing inference

Implementing a live pair head before the target registry and binding core are authoritative would force it to trust caller-supplied target/version/digest values. That would let an apparently approved pair outlive a changed location binding and would not satisfy the existing M8-C design. The safer sequence is:

1. Finish the independent exact-HEAD review of the frame reader. Keep its output internal and pair writes inactive until that gate closes.
2. Review and implement the Take target registry plus Production Preparation binding create/CAS/snapshot authority from ADR-0102. Preserve current screenplay admission as upstream authority; do not treat a derived target as a new human approval.
3. Implement pair admission against exact current target and `LOCATION` binding heads, after locking those heads and both sorted distinct parent master keys. Reuse `SpatialFrameReader.read_locked` in that transaction, bind immutable decision evidence and reviewer authorization, then append the decision and advance one scoped current pair head atomically. Test APPROVE and REJECT, changed target/binding/parent/frame, wrong scope, duplicate role, replay, rollback and concurrent re-admission on PostgreSQL.
4. Only after the pair head is accepted should spatial preview and promotion consume its exact ID/version/digest and recheck it under the M8 lock order. C1 candidate evidence may remain separate from this promotion gate.

This sequence is a design inference from the cited authority contracts. It does not attest that the fixture frames are visually suitable; an accountable authorized human decision remains necessary. No pair or target schema, provider call, live migration or production activation was performed in this research checkpoint.
