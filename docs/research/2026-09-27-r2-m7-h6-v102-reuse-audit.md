## Verdict

Reuse-first has been applied to the pure contract and physical-census work,
but **has not been fully applied or proven for the V1-02 integration**. The
remaining work is to compose existing readers and validators under one
approved, release-pinned field map, and to prove their differing failure
semantics against the same fenced source. A new generic scanner, serializer,
archive engine or DB backup mechanism would duplicate current work without
resolving reference authority.

The graph used for structural leads is the separate M7 checkout at generation
`2026-09-18T10:57:40Z`. Coverage for `project_tree_census.py`,
`grid_reference_probe.py`, `backup_fence.py` and `fence_evidence.py` is missing;
`version_manager.py` metadata changed. Those files and all material current
paths below were read directly in this worktree. The two donor checkouts still
report the pinned SHAs in the [donor comparison](2026-09-25-r2-m7-h6-backup-donor-contract-reuse.md)
with no tracked changes at this audit. This is a bounded seam review, not a
repository-wide absence claim.

## Next review gate

Create one release-pinned V1-02 field map from the existing project/DB surveys:
for every declared reference, state the schema version, writer, reader, raw
absent/null/empty/present behavior, logical root, required-byte predicate,
historical disposition and matching fixture. Reuse `scan_project_tree()` to
prove physical presence, the formal adapter only for formal claims, and the
grid probe only for raw grid fields. First reconcile V1-01 liveness and
Task/attempt states; then reconcile the reference map against `versions.json`,
project/profile/Manifest states, global assets, media and external-secret
dispositions. Do not implement the production classifier or capture adapter
until that map, deployment identity, fence, custody and sponsor gates are
approved. Fresh repository-integrated PostgreSQL and clean-target restore
tests remain separate acceptance obligations.
