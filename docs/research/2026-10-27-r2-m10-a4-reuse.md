## Tool and resource observations

Local primary commands `ffmpeg -version`, `ffprobe -version`, `ffmpeg -filters`
and per-filter help report FFmpeg/FFprobe 8.0.1. This build includes
blackdetect, freezedetect, silencedetect, ebur128 and subtitles; libvmaf is
absent. Binary SHA256s and command outputs are retained in the A3 handoff's
`a4-local-tool-inventory.json` and `a4-local-filter-help.json`.

Tool absence, reference invalidity and policy applicability require separate
outcomes. An invalid named/content/timing/geometry reference requires the
specified `M10_REFERENCE_INVALID` handling. A required unavailable tool needs
a typed fail-closed tool/evidence outcome. Absence alone cannot authorize an
`INAPPLICABLE` result or a no-reference score.

The [Linux getrlimit manual](https://man7.org/linux/man-pages/man2/getrlimit.2.html)
distinguishes address-space and CPU-time limits; its RSS limit has obsolete
Linux behavior, and NPROC applies to a real UID's threads. These controls alone
cannot be relabeled as per-job RSS/process-tree/wall-time proof.
The [kernel cgroup-v2 documentation](https://docs.kernel.org/admin-guide/cgroup-v2.html)
describes hierarchical memory/task controls, including documented memory-limit
overshoot/OOM behavior. Actual enforcement/delegation still needs fixtures.

Installed systemd is 259.5. A read-only user-manager query succeeded outside
the sandbox; app.slice reported unlimited MemoryMax/TasksMax. No unit was
created or changed. The versioned
[systemd-run manual](https://www.freedesktop.org/software/systemd/man/259/systemd-run.html)
describes transient services/scopes, exec startup confirmation and configurable
argument-variable expansion. The
[resource-control manual](https://www.freedesktop.org/software/systemd/man/259/systemd.resource-control.html)
describes cgroup-backed unit properties. The online 259 manual identifies 259.6;
installed capability and effective controller/cleanup behavior remain unproven.
This is a mechanism to investigate, not an architecture choice.

## Concrete fixture lessons from A3 qualification

The retained diagnostics exposed RAM-backed `/tmp` pressure from 7.2 GiB of
pytest data and a renderer encoding-mode change that affected 22 container bytes.
The failed pair's packet and decoded-frame hashes were equal; the original
byte-identical assertion then passed three independent runs with a fixed,
supported encoding mode. This qualifies the recorded test environment, not
production renderer behavior.

A later scratch path crossed group-writable repository ancestors and exceeded
Unix-socket path limits. Existing custody checks correctly refused it. A short
private 0700 disk path with trusted ancestors reran all 25 affected cases successfully
(43 passed, 3 baseline PostgreSQL skips across the two modules). Standard failed-only
pytest temp retention then bounded accumulated test data. Security checks and
timeouts stayed intact. Complete-log monitoring replaced tail-only progress
inspection; completed XML/exit status remain the result authority.

These are direct inputs to A4's path, resource, determinism and refusal fixtures.
