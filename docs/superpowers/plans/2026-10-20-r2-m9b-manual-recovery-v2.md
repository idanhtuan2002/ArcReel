# M9-B Manual Recovery V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Native inline execution is preserved from the original B plan; no per-task independent review loop or agent fan-out.

**Goal:** Recover the original independently authenticated manual upload after host reconstruction, and close policy-expired uncertain attempts with a truthful, immutable V2 terminal receipt.

**Architecture:** Add explicit `m9.acquisition.v2` contracts, a version-aware acquisition service and typed admission/publication/closure metadata, retaining the existing full command-key uniqueness. The host verifies original erasable Ed25519 seals using public keys; a separate offline fixture custodian owns its private key and immutable upload ledger. Production admission remains unavailable without a separately provisioned issuer; no production issuer or new provider is delivered by this plan.

**Tech Stack:** Existing Python 3.12+, Pydantic, SQLAlchemy async/PostgreSQL, Alembic, FastAPI, native filesystem primitives and existing `cryptography==50.0.0` resolution. No dependency change. Ed25519 upstream source commit is `dcb7050b807b00392fa9fe2eac7cb362fcf355cc` (tag50.0.0); direct API evidence is in `CUSTODY-SOURCE-RESEARCH-2026-10-20.md` and the assembled `CUSTODY-RELEASE-RESEARCH-2026-10-20.md`; upload uniqueness/process isolation are additional implementation tests, not properties supplied by Ed25519.

## Global Constraints

- Preserve V1 contracts/ports/digest bytes and accepted A authority; never edit the pinned original B release, A migration or old B migration.
- Existing command identity `(user_id, actor_id, acquire, command_id)` remains the one dispatch/replay guard across projects. A protocol version cannot create a second attempt under it.
- New public protocol `m9.acquisition.v2`; result domain `m9.command-result.v2`; no implicit upgrade of unresolved V1 attempts or parse-failure downgrade.
- `EXPIRED_UNRECOVERABLE` retains `RESPONSE_OUTCOME_UNKNOWN`, possible quota, original request identity; no outgoing transition, renewal, refund or same-command redispatch.
- The approved narrow NEEDS_OPERATOR exception authorizes objective policy closure only, never a claim of provider resolution or other operator powers.
- All source/store/capability/custodian I/O MUST occur outside SQL transactions. Store writes/reads/headers/deletion are port I/O too.
- Same-command replay returns retained state before port calls. Explicit reconstruction uses original refs/pinned code, never current path mappings or fetch_page.
- Content hashes/signatures/native IDs stay erasable unless every applicable class permits proof; no disguised proof in metadata/header/tombstones/logs.
- Original data-class fixture values remain metadata refresh60/retention120/proof allowed and excerpt refresh30/retention90/proof forbidden; mixed page uses the earliest non-null deadlines. Include earlier upstream custody deadlines; never reset them on copying.
- Native restart pairs around READY commit, dispatch claim/pre-dispatch, and publication-before-attach are mandatory. Deterministic faults cover every named boundary; changed sampled boundaries become mandatory real restarts.
- B admission-side erase qualification is not E integrated acceptance. No production activation/provider call, push, merge or M9-C/E release.
- One independent B acceptance pass, at most one repair, no automatic rereview. Existing count remains zero used. No independent per-task review passes.

## Review Focus

1. A protocol-switch replay using the same command across a different project must conflict before any port call (T1/T3/T5).
2. An erased upload version must remain spent; cleanup cannot enable re-ingestion under its old identity (T4/T7).
3. A permitted metadata field must not inherit a forbidden excerpt digest through a shared attestation/header (T2/T4/T7).
4. A worker paused through expiry/erase fencing cannot publish its already-normalized content after resuming (T3/T6/T7).
5. An old decoder with the same adapter label but changed code/dependencies must refuse reconstruction (T2/T5/T6).

## T2. Immutable binding, admission types, clocks and public-key verification

**Files:** Create `r2/opportunity/manual_admission.py`, `r2/opportunity/manual_admission_ports.py`, `server/services/m9_manual_authenticity.py` and their inventory unit tests.

- `AdmissionEnvelope`: schema/metadata digest, above bindings, phase/version, descriptors, immutable admitted_at, effective access deadlines and dispatch status. Phase enum RESERVED / READY / CLEANUP_PENDING / ERASED; PUBLISHED_UNATTACHED is a publication fact, not an invented committed row state. `PublicationHeader` carries only opaque refs/permitted metadata and receipt metadata digest. It has a separate independently signed metadata-only receipt, domain `m9.manual-publication-receipt.v1`; its preimage MUST exclude content digests, material signatures and native content. Verify this header signature and exact intent/scope/publication binding even after content expiry; an object writer cannot forge refs used for orphan cleanup.
- `AdmissionDeadlines`: immutable per-class original upstream clocks, admission-based clocks and effective refresh/retention minima. `AdmissionReadPermit`: opaque lease_id, scope/attempt/envelope version, operational flag, DB issued_at and expires_at no later than original effective deadline. `DispatchClaim`: opaque claim_id, full command key, attempt/version, envelope/version and DB claimed_at. `AdmissionClosureIntent`: closure_id, scope/attempt/version, exact dependent opaque refs, phase/version and fence DB time. `AdmissionDeletionReceipt`: same closure/version/ref set, per-object absence confirmation, permitted proof-only results and deletion time. `SealExpectation`: exact schema/key/scope/source/claim/command/query/attempt/descriptor/object/class/deadline metadata to compare to verified seal content. These types all live in manual_admission.py; no type stores a private key.
- `ManualUploadAdmissionPort.admit(request: AdmissionRequest) -> PublishedAdmission`; `ManualPublicationPort.lookup_receipt(publication_key: str) -> PublicationHeader | None`; `read_verified(envelope: AdmissionEnvelope, *, object_ref: str, permit: AdmissionReadPermit) -> bytes`; `delete_exact(closure: AdmissionClosureIntent) -> AdmissionDeletionReceipt`. These are async internal protocols, not mutations to frozen ports.
- `effective_admission_deadlines(grant, objects, *, admitted_at: datetime) -> AdmissionDeadlines`: per-class minima of original upstream deadlines and new admission-based bounds, preserving null only for explicitly unbounded rules. `require_admission_access(envelope, *, now: datetime, operational: bool) -> None` rejects retention at >= and operational refresh at >=. No new clock on recovery.

Signature preimage is `b"m9.manual-material-seal.v1\x00" + canonical_body_bytes`. Raw digest/signature exist only inside erasable seal, not expected SQL metadata. Return sanitized existing M9 integrity/unavailable errors without echoing input. Verifier never issues a seal.

## T3. Additive schema, typed repositories and lock order

**Files:** New model/repository/migration and mirrored integration tests from inventory. Modify B attempt model/repository and `lib/db/models/__init__.py`; update the fourteen migration test files enumerated in the inventory, keeping historical revision/down_revision assertions exact.

**Schema:** New revision `9b9c4a0e0002`, down_revision `9b9c4a0e0001`. Add non-null attempt `protocol_version` default `m9.acquisition.v1`, CHECK V1/V2; original full command unique constraint unchanged. Five scoped tables:

1. `m9_manual_admissions`: PK(owner,project,attempt_id), RESTRICT composite attempt FK, metadata JSON + digest, phase/version, admitted_at nullable only before READY, erasure fence/version.
2. `m9_manual_publication_intents`: PK(owner,project,publication_key), unique attempt_id, RESTRICT attempt FK; independent original-ref/receipt/phase metadata survives envelope corruption. No cascading erase.
3. `m9_manual_upload_leases`: PK(owner,project,claim_ref,upload_version,attempt_id), RESTRICT attempt FK; source/contract, active/spent metadata and closure binding. claim_ref is custodian-random, not digest-derived; private byte/provenance comparison ledger belongs to the fixture custodian, not this table.
4. `m9_manual_read_leases`: PK(owner,project,lease_id), RESTRICT attempt FK; purpose, attempt/envelope versions and original effective expiry, no content. SQL erasure fencing stops new permits; pending closure waits for admitted leases to drain/expire and a crashed read worker cannot extend them.
5. `m9_manual_closure_intents`: PK(owner,project,closure_id), RESTRICT attempt FK; phase/version, exact opaque refs/dependencies, permitted deletion receipts. Publication intent/closure metadata independently locates lost envelopes. No future E FK.

All table families have direct users RESTRICT FK, positive version checks and schema-enumerated phase checks. Intent/envelope paired refs and forbidden-proof rules are validated on every typed read, not a JSON label. Admission/snapshot provenance is stored with admission/attempt bindings; receipt version/digest covers the provenance pairing.

**Interfaces:** `ManualAdmissionRepository(session, *, user_id, project_name)` with async `reserve(request, *, expected_attempt_version) -> AdmissionEnvelope`, `attach(publication, *, expected_envelope_version) -> AdmissionEnvelope`, `claim_dispatch(attempt_id, *, expected_attempt_version, expected_envelope_version) -> DispatchClaim`, `begin_read(attempt_id, *, expected_envelope_version, operational) -> AdmissionReadPermit`, `release_read(lease_id) -> None`, `close_expired(attempt_id, *, expected_attempt_version, resolver_id) -> AcquisitionReceiptV2`, `begin_closure(attempt_id, *, expected_envelope_version) -> AdmissionClosureIntent`, `finish_closure(receipt, *, expected_closure_version) -> AdmissionClosureIntent`. DB time comes from the application transaction, not a caller timestamp. `ManualAdmissionTransaction` composes existing capabilities/query/policy/repositories in the same session and exposes this repository plus typed V2 attempt/snapshot/receipt operations; repositories flush, never commit or call ports. `HostManualAdmissionUnitOfWork` in server/services/opportunity_acquisition_v2.py provides async `transaction() -> AsyncContextManager[ManualAdmissionTransaction]`, reusing the application session factory and HostAcquisitionTransaction policy method; it owns commit/rollback, and no nested per-repository sessions are opened.

**Lock order:** ordinary command guard → host policy serialization → original capability ID-sorted guards → cohort head → query head → sorted scoped upload guards → attempt row → admission/publication rows → read/closure lease rows → snapshot/observation heads. Exact guard identity is scope+opaque claim_ref/version; hash collisions serialize, never substitute identity. Cleanup first loads immutable dependency metadata outside its mutation transaction, then locks ALL affected command guards sorted by `(user_id,actor_id,operation,command_id)` before taking shared upload guards; changed dependency/version aborts and retries planning. It never takes upload guard then a new command guard. No provider/custodian interaction inside these locks.
