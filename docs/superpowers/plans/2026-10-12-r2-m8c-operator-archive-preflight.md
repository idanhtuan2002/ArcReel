## Exact v1 directory names

The operator provisions an absolute root outside app, PostgreSQL and M7 backup roots. `archive/` is root-owned mode `0700`; `read/` is root-owned mode `0755` and only this directory is mounted read-only into the app. The first implementation accepts one approval, stored as `archive/approved/00000000000000000001.json`; it refuses any second approval until a continuity ceremony exists. The exact approved registry is retained at `archive/registries/sha256-<64 lowercase hex>.json`. High-water records are `archive/high-water/<20-digit sequence>.json`, starting at 1 without gaps. Exact signed envelopes are retained at `archive/checkpoints/sha256-<64 lowercase hex>.json`. The digest in each content-addressed basename is the SHA-256 of the complete file bytes. `archive/.publisher.lock` is a root-owned regular file. A private `archive/.staging/` holds incomplete temporary files during publication; only the operator can reconcile or remove these under the lock. No private signing key enters either subtree.

The public names are exactly `read/approved-deployment.json`, `read/governance-verifiers-v1.json`, `read/high-water.json` and `read/grant-checkpoint.json`. At preflight, each must be a regular root-owned mode `0644` file. Unknown permanent entries in `archive/` or `read/`, symlinks, hardlinks to mutable app roots, wrong owner/mode or size, missing sequence entries and duplicate/noncanonical names deny. Temporary entries are never accepted as authority; interrupted ones require an explicit operator reconciliation while the app remains stopped. Host-root control remains outside the claim.

## Read-only preflight

1. Open the root and each expected subtree by descriptor-relative, no-follow directory walks. Verify root/subtree owner and mode, then read bounded regular files with pre/post `fstat` identity checks. Do not accept a path merely because its string starts with the approved root.
2. Enumerate `approved/`, `registries/`, `high-water/` and `checkpoints/` with a bounded entry count and total byte budget. Check exact filename grammar and reject gaps, duplicates, unexpected types and unexpected retained file digests. The concrete capacity bound needs a benchmark before activation; do not silently truncate an archive.
3. Parse approval sequence 1; compare its registry digest to the retained registry bytes. For every high-water sequence, verify the previous high-water record digest, checkpoint-body predecessor, exact retained envelope file digest, signer/deployment/approved-record binding and signed checkpoint under the retained registry key. Check that prior scopes remain and grant-head sequences do not decrease in the ordinary chain. Do not trust a mutable `latest` pointer or a self-declared record digest.
4. Require all four public files to equal the corresponding latest retained bytes. Run `validate_public_custody_snapshot` on those bytes. Compare the actual resolved image digest/platform outside the container to the approved record in the operator release preflight; the app cannot prove its own image identity.
5. Run the read-only PostgreSQL schema preflight and full-chain scanner against the same latest checkpoint before starting workers or routes. A database restored to an older internally consistent checkpoint must still fail at archive/public comparison. Report only sanitized errors from app-visible paths; keep detailed operator diagnostics outside app logs.

## Offline publication and recovery

While app and workers are stopped, hold a bounded exclusive lock in `archive/`. Check the complete prior archive and public state, signed candidate successor and committed database through the full scanner. Write the exact candidate envelope and high-water record to private sibling temporaries, fsync their file contents, then publish them to create-only archive names and fsync their parent directories. A name collision with unequal bytes quarantines; a same-byte retry may continue only after the whole archive is reverified. The retained registry is create-only as well. Publish public `high-water.json` first and `grant-checkpoint.json` second using same-directory temporary files, file fsync, rename and `read/` directory fsync after each replacement. Mixed pairs deny. The app remains stopped through final operator preflight.

After interruption, validate the retained chain before touching `read/`. A complete latest retained entry and exact envelope can be replayed byte-for-byte; an incomplete final record, missing envelope, unknown temporary, divergent database or archive gap quarantines until an audited recovery procedure resolves it. Never lower the retained high-water to match a restored database. A separately stored, tested archive backup is required for host-loss recovery; its location and retention are still open.
