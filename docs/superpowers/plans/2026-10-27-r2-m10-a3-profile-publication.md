> **For agentic workers:** Use superpowers:executing-plans serially with test-driven-development. Do not implement before two actual independent design PASS records and separate pinned acceptance. Keep one independent whole-packet implementation review at the end.

**Goal:** Persist immutable scoped quality profiles through a qualified interactive-Human publication action, exact replay, CAS and atomic receipt/outbox writes.

**Architecture:** Preserve A0/A1/A2. Reuse their contracts/digests/errors and the verified host JWT/grant mechanisms; qualify a new action-specific issuer and M10-owned PostgreSQL transaction. No activation, router, provider or production migration.

**Tech Stack:** Existing Python, Pydantic, SQLAlchemy2.0.52, Alembic1.19.1, asyncpg0.31.0, PostgreSQL18 and pytest. No dependency changes.

**Spec:** docs/superpowers/specs/2026-10-27-r2-m10-a3-profile-publication.md

## Global constraints and review focus

- Exact manifest paths only; old contracts/domains/operations and prior gates are immutable. Only the named ORM registry additions are editable predecessor code.
- A data-only user/lease/row/digest is not authentication or custody. Actual interactive verification, issuer receipt and current signed/checkpointed grant must all agree.
- Database admission time is fetched after waits and authority I/O. Test lease expiry while blocked and grant revocation in both writer orders with PostgreSQL blocker evidence.
- Receipt-first historical replay does not renew authority or change the head. Hash collisions serialize guards, never merge full command identities.
- Migration/metadata parity and SQL append-only behavior require actual tests; a create_all-only success is insufficient.
- HISTORICAL_ONLY/REEVALUATE_CURRENT tests in this packet cover the predicate and durable intent only. Actual readiness integration remains A5.
