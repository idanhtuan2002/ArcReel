# R2 V1-06 — paid routes, qualification, E1 and upstream backport (plan)

- **Decision:** ADR-0091.
- **Research:** `docs/research/2026-09-28-r2-v1-06-paid-routes-and-e1-remediation.md`
  and `docs/research/2026-09-28-r2-v1-decision-audit.md`.
- **Base:** branch `feat/r2-m7e-v1-lineage`.
- **Sequencing:** packets run in order of risk. Each packet ends with its
  targeted tests, the static gates and a commit. Full suites run only at the
  V1-06 closing gate.

## Global rules

- **Upstream commits** are applied with `git cherry-pick -x` when they apply
  cleanly (disposition `UNCHANGED`). Otherwise the fix is re-implemented and
  the commit cites the upstream SHA (`ADAPTED`). Upstream tests are ported
  with the fix.
- **i18n, comments and test tiers** follow AGENTS.md and CONTRIBUTING.md.
  Subprocess tests go in the integration tier.
- **Nothing here issues a paid call.** Canary execution stays an operator
  action.

## Packet P2 — outbound destination and byte-cap guard (U3, `ADAPTED`)

**Scope.** Re-implement the intent of upstream `2c4ca6d6`, `8faf1450` and the
guard part of `3ff6127f` against V1's layout, which has no `lib/backends/`
package:

- one guarded HTTP client for provider submits, polls and artifact
  downloads;
- probes and model discovery use the same client;
- link-local and cloud-metadata destinations are refused; loopback and
  private networks are allowed;
- a byte cap on artifact downloads;
- cross-origin 307/308 redirects drop both the body and the credentials.

**Exit criteria:** the ported upstream guard tests pass, and every guarded
call site is covered.

## Packet P3 — generic paid-route invariants and release mode (ADR-0091)

1. **Ambiguity conformance.** Paid synchronous submits (image, text, audio)
   no longer retry on timeout or connection loss after the request may have
   been sent (ADR-0078). Retries remain for errors proven to occur before
   send, and for explicit 429/5xx responses from the provider. Test: a
   timeout after send produces exactly one attempt and a recorded
   ambiguous failure.
2. **Source-derived route inventory.**
   - The inventory covers the classes `media:{provider}:{media_type}`,
     `custom:{media_type}`, `agent` and `trial_run`.
   - A test enumerates `PROVIDER_SPEC_REGISTRY`, the `submit_video_attempt`
     call sites and the custom media types. An unlisted route fails the
     test.
3. **Fix the built-in MiniMax video binding** (`SubmitRouteUnboundError`),
   and close the taskless video submit bypass.
4. **Release mode.**
   - `ARCREEL_RELEASE_MODE` = `DEV` (default) | `PRODUCTION_CANDIDATE`.
   - In `PRODUCTION_CANDIDATE`, `assemble_backend`, Agent session start,
     trial-run start and the video submit seam refuse any route without a
     current qualification. The refusal carries a machine-readable code and
     an i18n message.
5. **Budget before submit.**
   - Wire `submit_with_budget_guard` for paid submits when the release mode
     requires it and a budget scope is configured.
   - With no scope configured in `PRODUCTION_CANDIDATE`, refuse the call.
   - This is scoped after reading the existing budget service. If it needs
     schema, record a stop.

## Packet P4 — E1 remediation (S1–S3, T1–T3)

- **S1 (upstream).** Verify `integration_method`:
  - `MERGE`: `new_sha` is an ancestor of `host_sha`.
  - Per commit: `UNCHANGED` needs a host commit with an equal stable
    patch-id in `rollback_target..host_sha`; `ADAPTED` needs a host commit
    whose message carries `(cherry picked from commit <sha>)` or
    `Upstream: <sha>`.
  - `DEFERRED` and `REJECTED` must be absent from the host range.
- **S2 (provider).** Parse the evidence content and require
  `result: "PASS"`, together with the bound `profile_ref` and digest.
- **S3 (gates).** The manifest names committed gate logs by digest. The
  verifier re-parses each log's summary: pytest `N passed`, no `failed` or
  `error`, no required skip, a non-zero count. A gate runner script produces
  the logs (T1).
- **T1–T3.** Move the subprocess tests into the integration tier, split the
  tests by tested object, and remove temporal wording.

## Packet P5 — two-level qualification and canary runner

- **Registry API.** Merge the static adapter profiles (`OFFLINE_VERIFIED`
  per adapter version, backed by fake-based profile tests) with the runtime
  route qualifications. These are deployment records keyed by exact
  provider, endpoint, model and adapter version, with an expiry.
- **Canary runner.** The operator starts it through the API and the CLI. It
  makes one bounded call under budget, and records the evidence (T1 shape)
  and the qualification.
- **Enforcement.** The release-mode checks in P3 read the registry API.
