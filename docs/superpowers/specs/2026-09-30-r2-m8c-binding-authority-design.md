# R2 M8-C ProductionBinding authority and spatial promotion design candidate

Status: **proposed**. Depends on ADR-0102 review and acceptance. This packet extends the accepted M8 spec only at the missing `PRODUCTION_BINDING` authority seam; it does not redefine M8-A's artifact-slot path or release M8-C C2.

## Why this packet exists

The frozen domain model makes `ProductionBinding` the semantic-to-production bridge. The accepted M8 spec targets that bridge for `SpatialCandidate`, and ADR-0095 requires a persistent CAS writer before promotion. The inspected R2 source has only in-memory binding and target values; the M8 preview API rejects the binding target; the prompt planner has no typed spatial input. [Source inventory](../../research/2026-09-30-r2-m8c-production-binding-authority.md) and [consumer comparison](../../research/2026-09-30-r2-m8c-consumer-options.md) record the bounded evidence.

## Authority model

| Object | Owning write path | Identity and immutable content | Read rule |
| --- | --- | --- | --- |
| Production target | Production Preparation | project, `SCENE`/`SHOT`, ID, version, canonical `SceneSpec`/`ShotSpecV2` digest, exact screenplay admission ref and derivation version | Exact derived version; a shot also resolves its scene in the same project |
| Production binding | Production Preparation | project, binding ID, monotonic version, exact v1 body digest, optional spatial-set ID/digest, envelope digest | Head for admission, exact version for snapshot/readiness |
| Spatial constraint set | Production Preparation via M8 authorized promotion only | immutable ID, digest, exact candidate revision/digest, selected visible assertion IDs, source media IDs/digests and source spans | Exact set only through a binding version |
| M8 candidate/preview/authorization/receipt | M8-A authority | existing IDs and digests plus typed spatial proposal and binding expected head | Exact revision and preview, same transaction as binding update |

Target registration is necessary because a binding's `target_id` otherwise has no checked production identity in the inspected host. The first supported target family is Take-derived scene/shot. The registration command takes an exact `AdmittedScreenplayRef`, re-reads it through `ApprovedScreenplayReader.get_exact_admitted` (which verifies the current admission head, decision and content hash), runs `TakeDirectorAdapter`, requires the derived target's `approval_status=APPROVED`, and stores the selected scene/shot digest plus screenplay/admission refs and derivation version. It verifies shot-to-scene identity in the same derived result. Registration records that proof; it cannot independently approve a caller-constructed target. Other Director families are unsupported until their exact upstream admission and derivation proof is reviewed. Target and binding creation stay outside M8 promotion.

The first spatial source family is exactly two project-scoped, approved M7 master heads and their immutable candidate objects. Each source ref includes artifact key, master version, candidate ID and content digest. `DatabaseMasterResolver.get_exact` must check current master identity and legacy divergence, and `CandidateObjectRepository.get_exact` must match the registered object and digest. Execution rehashes source bytes before sending them to the model. A non-master or a mutable asset URL is unsupported in this packet.

The binding version envelope preserves the v1 `ProductionBinding` field schema and does not change existing fixture serialization. It adds only spatial-set identity and digests around that body. `LOCATION` is the only role eligible for the first M8-C spatial update. An update increments the body's `version` and copies every other v1 field unchanged; it cannot change the target, semantic/production refs, role or asset refs. Other binding edits use a separate Production Preparation command and their own typed validation.

Every stored digest uses a named domain and canonical JSON version. Digests cover all identity and content fields, including source media references, source spans, assertion IDs, classifications, locks and normalizer version. The snapshot digest covers ordered `(binding_id, version, envelope_digest)` tuples and the exact target-version digests. Digest input and bytes must be fixed in a test vector before schema implementation. A reader rehashes stored bodies rather than trusting a digest column.

## Spatial evidence and mapping

A validated candidate revision retains the donor-derived visible/inferred/gap distinction, overlap deduplication, seam topology, direction exclusions, source references and normalizer version. The accepted `SpatialAssertion` had generic `relation` and `subject_refs`; the C1 work in progress adds optional typed `source_spans` while preserving old assertion JSON bytes. A span for the first two-still-image path is a normalized object-level image rectangle (`source_ref`, `source_digest`, `view`, `x0`, `y0`, `x1`, `y1`, each coordinate within `[0,1]`, positive area) tied to an exact M7 master/candidate digest. A shared side anchor may carry one rectangle from each view. A coarse whole-image or side-crop label is insufficient to establish that an individual asserted object is visible. An empty or unresolvable span fails closed. The provider/model result is evidence only.

The pinned DramaClaw prompt explicitly instructs its model not to output bbox or original-image coordinates (`scene_spatial_contract.py:274-280`). That behavior cannot satisfy the accepted M8 source-span requirement. R2's spatial prompt/schema must request the rectangle, and its validator must reject a `VISIBLE` item without one. The donor differential should still compare selected overlap/direction normalization on the same spatial fixture. This source-span change is an intentional donor correction: retain a donor fixture that lacks the span and an R2 regression fixture that rejects or downgrades it rather than fabricating coordinates. It must be marked `IMPROVED` only after the exact fixture/test evidence passes.

The typed preview proposal names an existing binding, selected assertion IDs and a constrained spatial mapping. It cannot supply a new `ProductionBinding` body. The adapter validates every selected assertion as `VISIBLE`, resolves its exact M7 master/candidate digest and span, rejects contradictory direction/seam constraints and records omitted `INFERRED`/`GAP` rows in the impact view. The proposal's canonical digest is part of the preview. The human authorization binds that digest and an expiry. The resulting immutable set carries structured constraints and provenance, not a prose prompt fragment.

The candidate normalizer and its donor differential can be implemented before this authority. The exact selected donor behavior is spatial normalization in `scene_spatial_contract.py`; the donor 360 builder is a consumer comparison, not automatically part of the selected parity surface. The parity contract must state this boundary and run same-fixture donor/R2 behavior for every selected material row under R2-DEC-031. A donor correction needs a failing donor fixture and stronger R2 expected result.

## Write and replay protocol

The Preparation writer uses one database transaction. It scopes every query by user and project, verifies the actor and project access before writing, locks the command key, locks the binding head, revalidates exact target/media content and expected head version, appends one immutable version and advances the head. A request with expected version zero can create a binding only through the separate Preparation create command. M8 always requires an existing positive head.

For M8 promotion, lock order is command key → candidate head → preview → binding head → target/source authority rows. The target registry and M7 master rows must be checked through the same PostgreSQL session as M8, including current upstream screenplay-admission head verification; a separate `ApprovedScreenplayReader` unit of work cannot provide an atomic currentness check during promotion. The transaction checks authorization scope, candidate revision/body digest, selected assertion classifications, preview digest/expiry, binding version/envelope digest, target version/digest, source media digests and the constraint proposal digest under those locks. It stages the immutable constraint set and binding version, authorization, promotion receipt and command receipt, then commits once. An exact command replay returns its stored result before currentness checks; the same command ID with a different body fails. Storage failure rolls back all staged rows. Lock acquisition and transaction ownership must be shared with the existing M8 promotion adapter rather than nested commits.

The preview read is non-mutating. It binds the exact expected head and names effects on readiness/fingerprints and the prompt consumer. The current untyped `impact` field remains explanatory only. Promotion may not turn a gap or an inferred claim into a visible production fact.

### Spatial wire and persistence arm

Keep the accepted artifact-slot `PromotionPreview` and `PromotionReceipt` models, bytes and digest domain unchanged. Add a separate `CreateSpatialPromotionPreviewRequest` endpoint with `candidate_id`, `candidate_revision`, `binding_id`, `expected_binding_version`, `selected_assertion_ids`, typed `SpatialConstraintProposal` and `command_id`. The proposal contains only typed relation/seam/direction selections and exact M7 source refs; it cannot carry a binding body. Its digest uses a new domain and canonical version. The server resolves the binding and sources, never trusts client digests, and returns a `SpatialPromotionPreviewV2` containing the existing preview identity fields plus the binding envelope/target/source/proposal digests. The authorization's existing `preview_digest` refers to the V2 digest. Binding target requests to the existing generic preview route remain unavailable.

The existing `m8_promotion_previews` row supports a `PRODUCTION_BINDING` target but has no typed proposal columns. Add a `m8_spatial_preview_bindings` sidecar keyed by scoped `preview_id`, holding the V2 schema discriminator, canonical typed proposal, selected assertion IDs, binding and target identities/digests, and ordered source identities/digests. The V2 digest covers base-row fields plus the sidecar; the repository requires exactly one sidecar for a binding target and none for an artifact slot. No binding preview row existed under ADR-0095, so old preview bytes remain untouched. Add an analogous scoped `m8_spatial_promotion_results` sidecar keyed by `receipt_id` with binding version/envelope digest and constraint-set ID/digest; the existing receipt row's `result_master_id` stays null. A V2 result reader rehashes both rows. Migration and corruption tests must enforce coupling at read and database constraint boundaries. The existing M8 command-key namespace is reused, so replay cannot cross wire arms.

## Read and consumer protocol

The snapshot resolver returns exact binding versions and verifies envelope, v1 body, spatial set and target digests. ProductionReadiness evaluates this resolved set and records the snapshot ID. Content fingerprinting includes the snapshot digest so a spatial-only update changes the fingerprint. A stale readiness snapshot cannot authorize later use. Existing pure Golden fixtures continue to work as offline fixture inputs; they are explicitly tagged as such and cannot be used as live authority reads.

The R2 prompt planning/compilation seam takes a typed resolved spatial set from an exact `LOCATION` binding, emits only supported visible constraints, and records the binding snapshot in the prompt plan/fingerprint. An inferred region or gap is represented as a coverage warning, never as a positive scene fact. Same-fixture tests must show that the binding changes the compiled semantic prompt and that omission does not invent topology.

The consumer gate also requires one reachable application entrypoint for a Take-derived shot. It must resolve the current approved target and binding snapshot, evaluate readiness with that snapshot, recheck currentness inside admission rather than trusting the caller-supplied `readiness_is_current=True` default, compile the prompt with visible spatial constraints, and bind the snapshot identity and compiled request digest through queueing and M7 attempt submission. A stale or corrupt read fails before provider submission. The existing `/projects/{p}/generate/video/{segment_id}` path accepts an independent prompt and disk script, so it cannot be treated as this entrypoint merely by calling `PromptPlanner` in a test. The existing queue's `reference_video` task rereads mutable script content at execution, so it cannot carry this exact snapshot either. A dedicated R2 shot-generation route and task type must persist the exact target/binding snapshot, compiled prompt digest, source media identities and command key; the worker re-resolves and revalidates them at claim and immediately before M7 attempt submission. No path may silently fall back to a caller prompt or disk script on mismatch. The route, task payload and worker/submit fingerprint are a public contract change and require independent review before use. M8-C acceptance requires a traced application-route-to-submit test, not only Golden-script output.

## Packet and acceptance order

1. **Design gate:** review ADR-0102 and this spec against frozen R2 decisions, current source and exact Take-screenplay/M7-master custody seams. Freeze digest vectors, V2 wire models, route-to-submit identity binding, the transaction lock order and a migration; publish a reviewed execution-contract amendment, implementation plan and allowlist. No acceptance claim follows from author self-review.
2. **Authority gate:** implement target registration, binding create/update, CAS storage and exact snapshot resolver. Test cross-project access, stale head, changed replay body, partial transaction failure, row corruption, target mismatch, source custody and concurrent updates in PostgreSQL. Independently review exact HEAD.
3. **Consumer gate:** implement immutable typed spatial set, R2 prompt consumer and one reachable application generation entrypoint; prove readiness/fingerprint invalidation, same-fixture prompt effect, request digest binding and a route-to-M7-submit integration path. Independently review exact HEAD.
4. **M8-C gate:** implement C1 normalizer and candidate append/execution; then typed preview and atomic C2 promotion through the accepted authority. Run donor differential, fault/replay and affected-domain gates, seal exact integrated HEAD and independent review. M8-D remains gated on full M8-C acceptance.

Open design items for gate 1: confirm that Take-derived targets cover the first M8-C vertical slice; prove the two chosen source image slots are representable as approved M7 masters in one fixture; freeze canonical digest test vectors and database lock order with existing M8 rows; define the exact queue/submit binding field and eligible mapping from selected visible spatial relations to typed constraints. These are required design work, not waivers.
