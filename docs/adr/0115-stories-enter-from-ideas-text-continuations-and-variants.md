# Stories enter the pipeline from an idea, an existing text, a continuation or a variant

Decided 2026-11-09 by the main agent under the sponsor's instruction to make the pipeline accept an existing finished or unfinished story, continue a story, and write variants of a finished story — by human request or automatically — with tools no weaker than the donors'. Research: [donor writing capabilities](../research/2026-11-09-r2-donor-writing-capabilities.md) (huohuo, DramaClaw, shenbi, novel-studio-ai, ViMax, OpenMontage, take, StoryBox), building on [ADR-0114](0114-film-episodes-are-adapted-from-the-story.md): the story is a product; films are adapted from it.

Before this decision a run could only start from an idea (`RunCommand` "start requires idea"), and the story engine wrote a new 3-chapter story every time. A story written elsewhere could be uploaded to a project and turned into video only through the manual workflow; nothing continued a story or forked a variant.

1. **Automatic run from the project's story (`story_source = project`).** A run may start without an idea when the project's sources hold the story. It begins at `ASSET_ANALYSIS`: `BRIEF`, `STORY`, `STORY_COMMIT` and `HANDOFF` are not run, and a changed input restarts the run there too. The project's source text is part of the run's input witness, so editing or appending the story mid-run stops it as an input change. The start is refused (`PROJECT_SOURCE_MISSING`) when the project has no source text. The project's existing upload path (txt/md, chapters appended over time) is the import door; episode planning already appends new episodes for appended chapters without touching planned ones, so an unfinished story can be produced as it grows (DramaClaw's import-first flow; its format preview maps to the existing workflow blockers). The field is left out of a stored command at its default, so earlier commands keep their digests.
2. **Continuation (`story_source = continue`, or a story-run brief with `prior_mode = continuation`).** A continuation writes the next chapters of a committed story — the project's own or an imported one — and adds them as a new source file, so 1 then films them. It rebuilds context from the committed text, never from memory: a canon lock of the last known state (huohuo `NC:141`), the previous chapter's tail and a summary chain of earlier chapters, the open hooks, and the author's direction (shenbi `sequel-writing`); committed text is never edited. The story run reads the prior text inside its own ledger: one `prior_summary[k]` node per chunk of about 8 000 characters (at most the last 12 chunks), then a `canon_lock` node (characters with their current state, places, events, open threads, ending state, voice) whose names must be written in the prior text. The canon lock and the author's direction precede the seed, bible, outline and chapter-plan prompts (and are inputs of those nodes), and the first scene opens right after the prior text's last 1 500 characters. The new part is handed to the project's sources under a name that sorts after every story file, so episode planning continues after the planned episodes.
3. **Variant fork (`story_source = variant` with `source_project`, or a story-run brief with `prior_mode = variant`).** A variant is a new manuscript written from a committed story under a digest-bound variant spec — what to keep (plot spine, characters, ending), what to change (style, tone, POV, genre, market, age rating, language) and its origin (a human instruction or a named profile). The original stays committed; the variant records the version it forked from (shenbi `canon-import` keep/change lists, huohuo genre packs, novel-studio style revision), and the variant context holds the source's events in order as the plot spine to keep. A variant is written into another project (the run's), never into the source project, so the original's sources and episodes are untouched. It reads the whole source (refused when longer than 12 chunks) and does not open on the source's ending. Named profiles (`first-person`, `darker-tone`, `light-comedy`, `young-readers`, `western-market`, `romance-focus`, `mystery-focus`) are specs an automatic run applies without a human note; a human instruction may add to one. The engine stays at its short-story scale (three chapters); a variant of a long novel is therefore a retelling at that scale.

Not adopted: StoryBox character simulation and ViMax's unused script planner (research §4 "What not to adopt"), donor score gates that grade skills rather than output.
